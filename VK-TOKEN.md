# Доступ к ВКонтакте

Радару нужно по расписанию читать записи со стен четырёх сообществ конкурентов:
`mangotelecom`, `roistat`, `qolio`, `speechanalytics`. Читать автоматически,
без человека за клавиатурой.

ВКонтакте отдаёт такие записи только тому, кто предъявил **токен** — длинную
строку-пропуск, выданную на конкретное приложение. Этот файл о том, как такой
пропуск получить и что с ним потом делать. Всё описанное уже проделано
18.08.2026, доступ работает; инструкция нужна на случай, когда его придётся
получать заново.

## Главное, что определяет всю настройку

Пропуска у ВКонтакте бывают четырёх видов, и три из них для нашей задачи не
работают. Это выяснено не по документации, а попытками:

| Вид пропуска | Читает стены сообществ |
|---|---|
| Сервисный ключ приложения | Нет. Отвечает ошибкой 28 «метод недоступен сервисному токену» |
| Ключ сообщества | Нет. Отвечает «метод недоступен при входе от имени группы» |
| Пропуск мини-приложения | Да, но живёт примерно сутки и выдаётся только внутри ВКонтакте |
| **Пользовательский пропуск через VK ID** | **Да. Его и берём** |

Из этого следует всё остальное. Пользовательский пропуск выдаётся только
приложению, у которого заполнены поля «Базовый домен» и «Доверенный Redirect
URL» — поэтому их придётся заполнить, хотя никакого сайта у нас нет. Подойдёт
значение `localhost`, подтверждать владение доменом не нужно.

В [плане работ](../Радар%20конкурентов%20—%20контекст%20для%20разработки/04-tehnicheskij-plan.md)
был записан риск: «пропуска мини-приложений живут сутки, для работы по расписанию
нужен долгий». Он закрыт. Пользовательский пропуск живёт
около часа, но вместе с ним выдаётся вторая строка — `refresh_token`, по которой
программа берёт себе новый час сама. Человек в этом не участвует.

## Шаг 1. Создать приложение на dev.vk.com

Приложение здесь — просто запись в кабинете разработчика ВКонтакте, от имени
которой мы спрашиваем доступ. Ничего писать и публиковать не нужно.

1. Открыть https://dev.vk.com → **Мои приложения** → **Создать приложение**.
2. **Название** — `Радар конкурентов`. Его видно только в окне, где вы
   разрешаете доступ.
3. **Платформа** — **Веб** (сайт). Не «VK Mini App»: у мини-приложения пропуск
   живёт сутки и выдаётся только внутри ВКонтакте.
4. **Базовый домен** — `localhost`
5. **Доверенный Redirect URL** — `http://localhost`
   Именно так: `http`, без номера порта, без косой черты в конце. Написать
   `127.0.0.1` нельзя — для ВКонтакте это другой адрес, и он не подойдёт.
6. Создать приложение и переписать себе его **ID** — это номер, он понадобится
   на следующем шаге.
7. Убедиться, что приложение **включено**. Выключенное не пускает в окно доступа.
8. В правах доступа нужен пункт `wall` — разрешение читать стены. Если ВКонтакте
   попросит заполнить описание и отправить приложение на проверку — отправьте,
   иначе в окне доступа не появится пункт про стену.

Поля «Защищённый ключ» и «Сервисный ключ» в кабинете заполнены, но нам они не
нужны и никуда не вписываются. Схема получения пропуска устроена так, что секрет
приложения в ней не участвует вовсе.

## Шаг 2. Получить пропуск

```
python vk_token.py auth <номер приложения>
```

Дальше по шагам:

1. Программа откроет окно ВКонтакте с вопросом, разрешаете ли вы доступ.
2. Вы нажимаете «Разрешить».
3. Браузер уйдёт на адрес `http://localhost/?code=...` и покажет ошибку
   «Не удаётся получить доступ к сайту». **Так и задумано** — никакого сайта по
   этому адресу нет, он нужен только чтобы ВКонтакте вернул нам код в адресной
   строке.
4. Скопировать из адресной строки браузера **весь адрес целиком** и вставить в
   программу. Из него берётся код, который меняется на пропуск.

Проверить, что всё живое:

```
python vk_token.py test
```

Программа покажет, от чьего имени работает пропуск, и по каждому из четырёх
сообществ — сколько там записей и когда была последняя.

## Шаг 3. Что происходит дальше, при работе по расписанию

Перед каждым обходом программа обновляет пропуск:

```
python vk_token.py refresh
```

Здесь есть тонкость, о которой стоит знать заранее. При каждом обновлении
ВКонтакте выдаёт новую строку `refresh_token`, а старая перестаёт действовать.
Программа сама перезаписывает файл `vk_tokens.json` новыми значениями. Но если
обновление прошло, а обход после него сломался, повторить обновление со старым
файлом уже не выйдет — придётся заново пройти шаг 2.

Передать пропуск сборщику страниц:

```
$env:VK_TOKEN = python vk_token.py show
```

## Если программа ругается на сертификат

Ошибка выглядит так: `CERTIFICATE_VERIFY_FAILED: unable to get local issuer
certificate`. Означает она вот что: чтобы убедиться, что на том конце
действительно ВКонтакте, Python сверяется со списком доверенных удостоверяющих
центров. В хранилище Windows нужного центра нет — браузер в таком случае
докачивает его на лету, а Python так не умеет.

Лечится установкой готового списка:

```
python -m pip install --upgrade certifi
```

Тем же списком пользуется библиотека, которой радар ходит на все остальные сайты,
так что это лечится один раз на весь проект.

## Про секретность файла

`vk_tokens.json` — это и есть доступ к ВКонтакте от лица владельца аккаунта.
Внутри четыре важные строки: сам пропуск, строка для его продления, служебные
данные аккаунта и его номер. В git этот файл не кладётся, в `config.yaml` не
переносится.

Отдельно — про права на файл, чтобы не было ложного спокойствия. Программа просит
операционную систему поставить файлу режим `600` — «читает и пишет только
владелец», — но **на Windows такого режима просто нет**: там права устроены иначе,
и эта команда умеет разве что снять или поставить флаг «только чтение». Если
открыть папку через Git Bash, он покажет `644` («читать могут все») — это его
собственная выдумка для совместимости, а не настоящее положение дел.

Настоящие права проверены отдельно, командой `icacls`. Полный доступ к файлу
имеют только система, администраторы компьютера и владелец профиля. Групп
«Все» и «Пользователи» в списке нет — значит, от других учётных записей на этой
машине файл уже закрыт, и делать ничего не нужно.

Если однажды понадобится закрыть его даже от администраторов:

```
icacls vk_tokens.json /inheritance:r /grant:r "%USERNAME%:F"
```

Защита от утечки через git — отдельная история и от прав на файл не зависит.
Файл закрыт списком [.gitignore](.gitignore), составленным раньше, чем git
появился в папке; как это проверялось — в [FAZA-1-OTCHET.md](FAZA-1-OTCHET.md).

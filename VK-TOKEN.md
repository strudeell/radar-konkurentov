# Токен ВКонтакте для `wall.get`

Что нужно радару: читать стены четырёх сообществ (`mangotelecom`, `roistat`,
`qolio`, `speechanalytics`) методом `wall.get` по расписанию, без человека за
клавиатурой.

## Главное, что определяет всю настройку

`wall.get` принимает **только пользовательский ключ доступа**:

| Тип ключа | Нужен домен/redirect | Работает с `wall.get` |
|---|---|---|
| Сервисный ключ приложения | нет | **нет** — ошибка 28 `method is unavailable with service token` |
| Ключ сообщества | нет | **нет** — `method is unavailable with group auth` |
| Токен мини-приложения (VK Bridge) | да | да, но живёт ~сутки и требует запуска внутри ВК |
| **Пользовательский токен через VK ID** | да | **да** — этот и берём |

Отсюда и берутся поля «Базовый домен» и «Доверенный Redirect URL»: без них
VK ID не отдаст пользовательский токен. Заполняются они значением `localhost`,
подтверждать владение доменом не нужно.

Это закрывает риск из [04-tehnicheskij-plan.md](../Радар%20конкурентов%20—%20контекст%20для%20разработки/04-tehnicheskij-plan.md)
(«токены мини-приложений живут сутки»): у VK ID `access_token` живёт ~1 час, но
рядом выдаётся `refresh_token`, по которому новый час берётся без участия
человека. Фоновый сбор делает `refresh` перед каждым прогоном.

## Создание приложения на dev.vk.com

1. https://dev.vk.com → **Мои приложения** → **Создать приложение**.
2. **Название** — `Радар конкурентов`. Видно только в окне авторизации.
3. **Платформа/тип** — **Веб** (сайт). Не VK Mini App: у мини-приложения токен
   живёт сутки и выдаётся только внутри ВК.
4. **Базовый домен** — `localhost`
5. **Доверенный Redirect URL** — `http://localhost`
   Именно так: `http`, без порта, без слэша в конце. `127.0.0.1` не подойдёт —
   для VK это другой адрес.
6. Создать. В настройках забрать **ID приложения** (это `client_id`).
7. Состояние приложения — **включено**. Выключенное не пускает в авторизацию.
8. Права доступа: нужен scope `wall`. Если ВК требует заполнить описание и
   отправить на модерацию — отправить, без этого окно авторизации не покажет
   пункт про стену.

**Защищённый ключ и сервисный ключ здесь не нужны** и никуда не вписываются:
в схеме с PKCE секрет приложения не участвует.

## Получение токена

```
python vk_token.py auth <ID приложения>
```

Скрипт откроет окно авторизации ВК. После «Разрешить» браузер уйдёт на
`http://localhost/?code=...` и покажет «Не удаётся получить доступ к сайту» —
так и задумано, локального сервера нет. Скопировать весь адрес из адресной
строки и вставить в скрипт: из него берётся `code`, который меняется на токены.

Проверка, что всё живое:

```
python vk_token.py test
```

Выводит, от чьего имени работает токен, и по каждому сообществу — число постов
и дату последнего.

## Дальше, в фоновом сборе

Перед каждым прогоном:

```
python vk_token.py refresh
```

`refresh_token` при каждом обмене меняется, старый умирает — скрипт
перезаписывает `vk_tokens.json` сам. Если прогон падает, а обновление уже
прошло — повторный `refresh` со старым файлом не сработает, нужна новая `auth`.

Токен в переменную окружения для сборщика:

```
$env:VK_TOKEN = python vk_token.py show
```

## Если падает на проверке сертификата

`CERTIFICATE_VERIFY_FAILED: unable to get local issuer certificate` — в
хранилище Windows нет корневого сертификата, которым подписан `vk.com` (Google
Trust Services R1). Браузер докачивает такие корни на лету, Python — нет.
Скрипт берёт корни из `certifi`; если его нет:

```
python -m pip install --upgrade certifi
```

Тем же набором корней пользуется `httpx`, которым радар ходит на остальные
источники, — то есть лечится один раз на весь проект.

## Секреты

`vk_tokens.json` — это доступ к аккаунту ВК от лица владельца: `access_token`,
`refresh_token`, `id_token` и `user_id`. В git не кладётся, в `config.yaml` не
переносится.

Про права на файл, чтобы не было ложного спокойствия: скрипт вызывает
`os.chmod(..., 0o600)`, но **на Windows это не выставляет права 600** — там
POSIX-режима нет вовсе, `chmod` умеет только снять или поставить флаг «только
чтение». Git Bash показывает `644` — это его эмуляция, а не настоящее положение
дел. Фактический доступ определяется списком ACL, и он проверен `icacls`:
`SYSTEM`, `Администраторы` и владелец профиля — полный доступ, больше никого.
Группы `Все`/`Пользователи` в списке нет, то есть файл и так закрыт от других
учётных записей машины. Ужесточать нечего; если однажды понадобится убрать даже
администраторов:

```
icacls vk_tokens.json /inheritance:r /grant:r "%USERNAME%:F"
```

Защита от утечки в git — отдельная и не зависит от прав: файл закрыт в
[.gitignore](.gitignore) до `git init`, проверено фактом (см.
[FAZA-1-OTCHET.md](FAZA-1-OTCHET.md)).

# Фаза 0. Разведка источников — отчёт

Дата: 18.08.2026. Задача фазы простая: до того как писать сборщик, руками
проверить, что каждый источник вообще отдаётся. Всё, что здесь написано, получено
живыми запросами к сайтам, а не вычитано из документации.

Результат — файл [sources.yaml](../config/sources.yaml): 19 конкурентов, **49 проверенных
страниц**, **11 проверенных каналов в соцсетях**. Автоматически собираются 17
конкурентов из 19: один игрок оказался мёртв, у одного стоит защита от роботов,
и его придётся смотреть глазами.

## Главный вывод: запасной план не понадобился

В плане была развилка: *если больше трёх сайтов откажут простому запросу
(ответят кодом 403 — «доступ запрещён»), переходим на программу-браузер
(Playwright). Она надёжнее, но медленнее и тяжелее.*

**Отказал ноль сайтов.** Кода 403 не отдал ни один. Восемнадцать из девятнадцати
спокойно ответили нашему боту, который честно представился именем `RadarBot/0.1`.
Ни одному сайту не пришлось притворяться живым человеком с браузером.

Значит, сборщик пишется на обычном лёгком запросе, как и планировалось, и тяжёлую
программу-браузер в проект тащить не нужно. Два исключения из девятнадцати
разбираются по отдельности, а не переделкой всего подхода:

| Сайт | Что не так | Что делаем |
|---|---|---|
| `aistudio.yandex.ru` | На всех внутренних страницах стоит защита от роботов — картинка с проверкой | Открывать руками раз в месяц. Продукт в закрытом тестировании, публично меняется редко |
| `call-intellect.ru` | Сервер обрывает соединение на полуслове | Игрок мёртв, из сбора исключён. Разбор ниже |

## call-intellect.ru: почему решили, что игрок мёртв

Это единственный сайт, который не отвечает вообще. Разбирались по шагам, чтобы
не спутать «сайт закрылся» с «у нас что-то не так с интернетом»:

- адрес сайта в сети находится, ему соответствует машина `45.67.59.118`;
- соединение с этой машиной **устанавливается** — и на защищённом порту 443,
  и на обычном 80. Машина на связи;
- но как только начинается разговор о защищённом соединении, сервер обрывает его
  молча, без объяснения;
- по незащищённому соединению — то же самое, пустой ответ;
- одинаково повторяется в трёх независимых программах: в нашем сборщике,
  в утилите `curl` и в браузере Chrome.

То есть машина жива и трубку берёт, но разговаривать отказывается. Похоже на
фильтр, поставленный на сетевом оборудовании.

Оставалась вероятность, что фильтр отсекает конкретно нас — например, по стране.
**Проверено 18.08.2026 с мобильного интернета, с российского адреса: сайт не
открывается и там.** Значит, дело не в нашем подключении. Сервер не отвечает
никому, и игрок считается мёртвым.

В [sources.yaml](../config/sources.yaml) запись помечена как мёртвая и из автоматического
сбора исключена, но **не удалена**. Причина: если её стереть, через полгода
кто-нибудь снова найдёт этот домен в списке конкурентов и повторит всю
диагностику с нуля. Игрок второстепенный, на запуск радара его отсутствие не
влияет.

## Ловушки, найденные при обходе

Каждая из них при наивной реализации сборщика давала бы ложные срабатывания —
то есть радар сообщал бы об изменениях, которых нет.

**Сайт отвечает «страница есть» на любой адрес** (на техническом языке это
называется soft-404). У `okk.ectem.ru` весь сайт —
одна страница. На любой запрошенный адрес он отдаёт её полную копию и говорит,
что всё в порядке. Наивный сборщик записал бы себе «страницу тарифов», которая на
самом деле меняется одновременно с главной, и каждое изменение приходило бы
дважды. Отсеяли сравнением текста с главной — совпадение оказалось стопроцентным.

**То же самое, но пустое.** `phonix.pro` на любой несуществующий адрес отдаёт
пустую заготовку в 1 987 знаков — ровно столько же, сколько на главной. Страниц
с ценами и интеграциями у них попросту нет, и служебный список страниц сайта это
подтверждает: в нём всего два адреса.

**Что из этого следует для сборщика:** ответ «всё в порядке» не значит ничего.
Страница считается существующей, только если её текст отличается от главной.
К проверке из плана «текста меньше 200 знаков — значит, сборщик сломался» нужно
добавить вторую: «текст совпал с главной — значит, страницы нет».

**Искать разделы по словам в адресе — плохая идея.** Первая версия проверялки
приняла за блог Roistat страницу `/ru/features/mediaplan` (сработало слово
*media* внутри адреса), а у Mango взяла отдельную статью вместо журнала целиком.
Лечится так: нужен не материал внутри раздела, а сам раздел — у него короткий
адрес и ключевое слово в самом конце. Это важно по существу, а не для красоты:
страница раздела меняется при каждой новой публикации, и это как раз тот сигнал,
который мы ловим.

**Служебный список страниц сайта надёжнее догадок.** Почти каждый сайт держит
файл со списком всех своих страниц — он делается для поисковиков. Оттуда берутся
точные адреса разделов и, что важнее, честно видно, каких страниц у конкурента
нет вовсе. Так подтвердилось отсутствие цен у Rechka.ai, phonix.pro, oneboost.io
и dialext.com.

## Правила для роботов: что разрешено, а что нет

У сайтов есть файл `robots.txt`, в котором владелец пишет, куда роботам можно,
а куда нельзя. Мы его соблюдаем. Запретов, которые нам мешают, не нашлось.
Несколько случаев стоит знать:

- **roistat.com** закрывает свой блог — но **только для робота Яндекса**. Общего
  запрета для всех в файле нет вовсе. Это борьба с дублями в поисковой выдаче,
  а не запрет обхода. Для нас открыто.
- **salesai.ru** держит грамотный файл: поисковикам и ИИ-поисковикам разрешено,
  роботам, которые собирают тексты для обучения нейросетей, запрещено. Наш бот
  попадает в разрешённые. Из закрытого — служебные разделы `/admin/`, `/demo/`,
  `/login/`, `/dashboard/`, `/strategy/` и файлы PDF. Нам они не нужны.
- **rodnik.bz** и **getcalls.ru** файла `robots.txt` не держат вовсе —
  ограничений нет.
- **okk.ectem.ru** закрывает один адрес `/tariffs_sber`. Мы его и не берём.

Отдельно: ни один сайт не выставил требования к паузе между запросами. Наши две
секунды между обращениями к одному сайту — с большим запасом.

План рассчитывал брать Дзен, YouTube, VC и Habr через готовые ленты, бесплатно.

**YouTube не берём, и причина техническая, а не «не хотим».** С рабочего

доступе и не долгий ответ, домен не определяется вообще. Без обходного канала
лента недоступна в принципе. Содержательно потеря невелика: видео мы всё равно

**Дзен тоже не берём автоматически, хотя хотели.** Сам `dzen.ru` открывается,
но дальше всё упирается:

- готовой ленты нет ни по одному из четырёх адресов, по которым она обычно лежит;
- страница канала приходит пустой заготовкой примерно на 2,9 КБ, живого текста

- есть служебный адрес, не описанный в документации, который отвечает и отдаёт

  а не публикации нужного канала — внутри «Техосмотр с 1 сентября» и светская
  хроника;
- второй служебный адрес, похожий на поиск по каналам, отвечает пустотой даже на
  запросы «новости» и «тинькофф». Как поиск он не работает.

Читать Дзен можно только программой-браузером. Ставить её ради второстепенного
источника — плохой размен: это ровно та тяжёлая зависимость, которую план
сознательно не берёт. **Решение: раз в месяц смотреть глазами.**

### Почему в подписи бота именно этот ящик

На каждом запросе бот представляется строкой:

```
RadarBot/0.1 (+https://okk-ai.ru; competitive monitoring; contact: example@gmail.com)
```

Это условие вежливого обхода из плана: у владельца чужого сайта должна быть
возможность написать нам, а не сразу заблокировать.

Взят публичный контакт с самого okk-ai.ru, а не заведён новый ящик. Причина —
проверяемость. Администратор конкурента видит в своих записях наш домен,
открывает сайт и находит там ровно этот адрес. Свежий `radar@okk-ai.ru`, которого
на сайте нет, так сверить нельзя, и выглядел бы он подозрительно. Плюс этот ящик
общий, не привязан к конкретному человеку, и переживёт смену сотрудников.

Что из этого следует и что нужно принять как данность:

- **Конкуренты узнают, что мы за ними смотрим.** Подпись честная и называет
  компанию. Это осознанный размен: анонимный обход лучше скрывает нас, но лишает
  права «пишите нам вместо блокировки» и повышает шанс попасть под автоматические
  фильтры.
- **В ящик могут приходить жалобы** от владельцев сайтов, вроде «уберите
  нагрузку», и, реже, реакция самих конкурентов. Это входящий ящик для клиентов —
  тот, кто разбирает почту, должен понимать, откуда такие письма.
  **Игнорировать их нельзя:** непрочитанная жалоба превращается в блокировку.
- **Спама заметно не прибавится:** адрес и так открыто висит на сайте, а сайты
  сборщики спама обходят гораздо активнее, чем чужие служебные записи.

Сменить ящик — одна строка `contact_email` в [config.yaml](../config/config.yaml), подпись
собирается из неё.

### Два расхождения с планом по библиотекам

План называл четыре библиотеки: `httpx`, `selectolax` или `bs4`, `PyYAML`,
`feedparser`. Разведка поменяла две позиции:

- **`feedparser` не нужен.** Он умеет читать готовые ленты, а ни одной ленты не
  осталось: из 60 точек сбора 56 берутся обычным запросом, 4 — через ВКонтакте.
  YouTube и Дзен отпали, больше лент взять неоткуда. Тянуть библиотеку под формат,
  которого нет, незачем — вернуть её ничего не стоит, если ленты появятся.
- **`selectolax` не нужен.** Вся разведка написана на `bs4` со встроенным
  разборщиком страниц, и он вывез все 19 сайтов. Второй такой же брать не за чем.

### Что было нужно закрыть до первого сохранения в git — закрыто в Фазе 1

На момент этого отчёта проект был **не под git**, а в `radar/vk_tokens.json`
лежал живой доступ к аккаунту ВКонтакте. Список исключений `.gitignore` должен
был появиться **раньше**, чем git, иначе доступ уехал бы в историю навсегда.
Туда же — служебный кэш Python и папка `data/_raw/` со 101 файлом, которые в
любой момент собираются заново.

Мелочь оттуда же: [VK-TOKEN.md](VK-TOKEN.md) обещал файлу с доступом права `600`
(«читает и пишет только владелец»), а Git Bash показывал `644` («читать могут
все»). На самом деле неверны обе цифры: на Windows такого режима прав нет вовсе.

**Как это закрыто:** список составлен до появления git, отсутствие доступа в
сохранённых файлах и во всей истории проверено фактом, обещание про права
исправлено. Подробности — в [FAZA-1-OTCHET.md](FAZA-1-OTCHET.md).

## Как повторить эту проверку

Примерно раз в квартал имеет смысл прогнать разведку заново: конкуренты
перестраивают сайты, и адреса разделов меняются.

```bash
python tools/stage_a_home.py       # главные страницы и правила для роботов
python tools/stage_b_pages.py      # поиск разделов по ссылкам и типовым адресам
python tools/stage_b2_sitemap.py <домены>   # список страниц для сайтов, где навигация рисуется в браузере
python tools/stage_b3_repick.py    # замена: раздел целиком вместо статьи внутри него
python tools/stage_c_verify.py     # отсев несуществующих страниц, проверка соцсетей
python tools/stage_e_curated.py    # финальная проверка выверенного списка
python tools/stage_d_build_yaml.py # сборка sources.yaml
```

Сохранённые страницы лежат в `data/_raw/`. Это заодно и точка отсчёта для
сборщика: первый обход источника — не изменение, а начало отсчёта.

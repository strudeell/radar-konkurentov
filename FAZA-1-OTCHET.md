## Что такое git и почему список делали первым

Git — система, которая хранит историю проекта: каждое сохранение (его называют
**коммит**) остаётся в ней навсегда. Это её достоинство и одновременно ловушка.

Файл `vk_tokens.json` — это доступ к ВКонтакте от лица владельца. Кто получит
файл, тот сможет читать и писать от вашего имени, пока доступ не отозван.
Если такой файл попадёт в git хотя бы один раз, удалить его следующим коммитом
недостаточно: он останется в истории, и достать его оттуда сможет любой, у кого
есть копия проекта. Лечится это только двумя действиями сразу — отозвать доступ
и переписать историю.

Отсюда правило: единственный надёжный момент закрыть файл — **до** того, как git
появился в папке. Что и сделано.

## Что закрыто, а что осталось на виду

**Закрыто от git:**

- `vk_tokens.json` и любые его копии с другими именами;
- файлы `.env`, где обычно держат пароли и ключи;
- служебный кэш Python и папка с библиотеками;
- `data/_raw/` — 101 сохранённая страница конкурентов, 45 МБ. Эти файлы в любой
  момент собираются заново запуском программ, хранить их в истории незачем;
- будущее содержимое папок `snapshots/` и `runs/`;
- мусор операционной системы и редакторов кода.

**Осталось в проекте сознательно:** программы `vk_token.py` и
`tools/check_vk.py`. Внутри них нет ни доступа, ни пароля — они только читают
готовый доступ из `vk_tokens.json` или из настроек компьютера, а номер приложения
человек вводит рукой при запуске. Без этих программ внешний разработчик не сможет
получить свой собственный доступ к ВКонтакте, а ссылки на них в
[VK-TOKEN.md](VK-TOKEN.md) вели бы в пустоту. Если решение изменится — закрыть их
можно одной строкой.

Результаты Фазы 0 (`data/phase0-*.json`) тоже остались: это проверенный вход в
следующую фазу, ничего секретного в них нет.

## Как проверяли, что доступ не утёк

Написать правило и написать **работающее** правило — разные вещи. Правило легко
составить так, что оно не сработает, и заметить это уже после утечки. Поэтому
проверяли не чтением файла, а на настоящем репозитории, пятью способами.

**Что реально готовится к сохранению.** Двадцать шесть файлов. `vk_tokens.json`
среди них нет, папок с кэшем и сохранёнными страницами тоже нет.

**Поиск самих строк доступа.** Искали не по имени файла, а по содержимому: взяли
каждое значение из `vk_tokens.json` и проверили, не встречается ли оно внутри
любого из 26 файлов. Совпадений ноль. Отдельно проверили номер аккаунта владельца.

**Поиск по приметам.** Доступ можно случайно вписать в код рукой, и тогда он не
совпадёт со строкой из файла. Поэтому искали ещё и по узнаваемым признакам:
ключи ВКонтакте начинаются с `vk1.a.`, служебные пропуска — с `eyJ`, плюс типовые
строки вида «доступ равно длинная абракадабра». Чисто по всем приметам.

**История.** На момент проверки в ней было ноль коммитов. Это и есть главное:
правило действует с самого первого сохранения, а не с какого-то момента после.

**Проверка на случай, когда git заведут уровнем выше.** Отдельно, в стороне от
рабочей папки, собрали копию ситуации: git на родительской папке, рядом папка с
контекстом для разработчика, а внутри — шесть поддельных файлов с доступом, нарочно
названных по-разному: `vk_tokens.json`, `vk_tokens.backup.json`,
`vk_tokens.2026-08-18.json`, `.env`, `.env.local` и `my.token`. Так проверяется,
что правило не цепляется за одно конкретное имя.
Ни один из шести в сохранение не попал. Значит, защита работает
и в этом случае: список действует на свою папку и на всё, что внутри неё,
независимо от того, где заведён git.

**Итог: чисто.** Доступ к аккаунту ВКонтакте в git не уходит.

## Чего эта защита не закрывает

Чтобы не было ложного спокойствия:

- **Файл никуда не делся, он лежит на диске.** Защита работает только против
  утечки через git. Она не мешает скопировать папку, отправить архив, положить
  проект в облако или подойти к этому компьютеру. Отдавая проект наружу,
  передавайте репозиторий, а не папку целиком.
- **Есть команда, которая обходит правило принудительно** — `git add -f`. Она
  существует ровно для таких случаев, когда человек точно знает, что делает.
  Для файла с доступом её набирать не нужно.
- **Задним числом правило не работает.** Если доступ однажды попадёт в
  сохранённую историю, добавление строки в список его оттуда не уберёт. В такой
  ситуации нужно сразу получать новый доступ: `python vk_token.py auth <номер>`,
  а старый считать скомпрометированным.
- **Опаснее всего строка `refresh_token`.** Сам доступ живёт час, но эта строка
  позволяет получать новый час без человека — то есть её утечка равносильна
  утечке постоянного доступа.
